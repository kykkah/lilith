**Tracing Module**
- `TracingAspect` supplies an AspectJ/Spring-AOP around advice that logs entry, exit, and exceptions, tagging MDC keys `tracedClass`/`tracedMethod` and emitting per-call timings via SLF4J markers (`tracing/src/main/java/de/huxhorn/lilith/tracing/TracingAspect.java:49`, `tracing/src/main/java/de/huxhorn/lilith/tracing/TracingAspect.java:230`). It is configurable for parameter echoing, short class names, modifier display, and lets you swap in a profiling handler (`tracing/src/main/java/de/huxhorn/lilith/tracing/TracingAspect.java:74`).
- `BasicProfilingHandler` and `StatisticProfilingHandler` provide the pluggable timing back end: one logs single-call durations with WARN/ERROR thresholds, the other aggregates counts/min/max/averages and periodically dumps a CSV-style table (`tracing/src/main/java/de/huxhorn/lilith/tracing/BasicProfilingHandler.java:41`, `tracing/src/main/java/de/huxhorn/lilith/tracing/StatisticProfilingHandler.java:49`).
- The tests show how it was meant to be consumed: Spring XML config wires the aspect against sample services and runs through assorted method signatures and exception paths (`tracing/src/test/java/de/huxhorn/lilith/tracing/TracingAspectTest.java:147`, `tracing/src/test/resources/defaultTracing.xml:1`).
- No Gradle build descriptor exists in `tracing/`, and the root `settings.gradle` only auto-includes other modules such as `lilith`, `log4j`, and `logback`, leaving `:tracing` out of the multi-project build (`settings.gradle:20`). Outside of this directory, the only references are historical release notes (`CHANGELOG.md:336`), so the code is effectively a legacy, off-by-default add-on that you would have to integrate manually if you still wanted AspectJ-based tracing in your application.
